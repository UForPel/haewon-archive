# Buttons and Actions Inventory

This file is a persistent UX requirement. **Do not forget visible buttons and user actions when implementing or redesigning features.** A feature is incomplete if its controls are missing, inert, confusing, inaccessible, or not verified.

## Current controls
- Main archive filters: All / Haewon keyword / Recent 7 days — filter records and update active state.
- Video pagination: Previous / Next — generated by the app and disabled at boundaries.
- Discovery category filters: generated category buttons — select category, reset page, rerender.
- Discovery pagination: Previous / Next — generated by discovery view and disabled at boundaries.
- Quick platform search: Search open — validates a query and opens the selected platform search.
- Photo-link form: Temporary link registration — validates, stores locally, refreshes list and source filter.
- Photo export: JSON export — downloads the browser-local draft data.
- Photo import: JSON import — reads selected file, validates entries, updates local draft data.
- Local photo entry deletion: Temporary entry delete — removes only the matching local draft and refreshes UI.
- Read-only discovery quality dashboard: reports thumbnail candidates found, actually assigned, duplicate rejected, missing/failed; shows source counts and recent RSS/OG/Twitter candidate provenance. No new action button.
- Date range, search, source and type controls are interactive filters, not buttons; they must still have clear labels and update results.

## Required behavior for every new or changed control
1. Record the control, purpose, expected action and disabled/error state here.
2. Use semantic buttons/links/forms; controls must be keyboard reachable and have accessible names.
3. Make the action actually work; never add a decorative button with no handler.
4. Show success/failure/empty feedback for data-changing actions.
5. Reset/retain pagination and filter state intentionally when actions change results.
6. Add automated coverage for markup presence and behavior where testable; manually verify responsive/mobile layout and the live UI when feasible.
7. Update this inventory, PROJECT_STATUS.md, ROADMAP.md when scope changes, and SESSION_LOG.md for substantial work.
8. Verify tests, the Actions run and Pages deployment separately. Do not claim live UI verification from CI alone.
